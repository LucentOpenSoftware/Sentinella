# Sentinella v0.1.12 — deep audit + verification pass

A security and correctness release. The full tree (all 11 crates, the Tauri GUI, and
the ClamAV integration glue) went through an independent deep audit, and then the
audit's own diff was re-reviewed adversarially — which caught three HIGH regressions
the audit had introduced while fixing other things.

> v0.1.11 was published as "the final release". That turned out to be premature:
> the audit surfaced real exploitable bugs, so development continued. This release
> supersedes v0.1.11 and everyone on it should upgrade.

## Install / Upgrade

**Existing v0.1.11 installs** auto-update from the GUI on next launch (the signature is
pinned in `tauri.conf.json` and validates against the same key).

**Fresh install / manual upgrade**: download `Sentinella_0.1.12_x64-setup.exe` below and
run it elevated.

## Why you should upgrade

These were live, locally exploitable:

- **`argus.analyze` UNC/device-path bypass (HIGH).** The handler was missing the path
  filter its sibling `scan.start` had, so any local process could make the SYSTEM
  daemon read an attacker-controlled SMB share or device path.
- **A dead-PID race bypassed the v0.1.9 elevation gate (HIGH).** Pipe identity
  resolution now fails *closed* when the calling process has already exited.
- **The IPC control plane could be killed by any local user (HIGH).** 64 held-open
  connections parked the daemon's accept loop indefinitely, hanging every GUI, tray and
  CLI request — an unauthenticated denial of service against an antivirus's entire
  management surface. (Introduced by the audit; caught in verification.)
- **A timed-out realtime scan was cached as CLEAN (HIGH).** A file whose signature phase
  exhausted the 10 s realtime budget had every heuristic layer silently skipped, scored
  0, and was written to the scan cache as clean — a *persistent* per-file whitelist that
  survived daemon restarts, and which also earned the file trust-graph credit.
  Reachable with deliberately slow-to-scan input. (Introduced by the audit; caught in
  verification.)
- **Scan-cache poisoning (HIGH).** The cache's content fingerprint covered only the
  first 64 KB, so keeping a file's header and size identical and restoring its mtime
  made the scanner skip it permanently. It now covers the whole file.
- **`clamavd` was calling libclamav wrong (HIGH).** `cl_scanfile` was invoked through a
  wrong 6-argument signature with a NULL `scanoptions`; corrected to the real 5-argument
  form with real options, and `cl_load` now uses `CL_DB_STDOPT`.
- **The reputation trust discount was forgeable with a self-signed certificate (HIGH).**
  It now requires a successfully *verified* Authenticode signer.
- **Sandbox containment gaps (HIGH ×2).** Network containment now sweeps the whole
  process tree so children are blocked too, and every restricted-launch fallback fails
  closed instead of running the sample under an unrestricted SYSTEM token.

Plus a fresh-install database migration wedge that permanently blocked all future
migrations, per-profile scan budgets that never actually reached the engine, an idle
scanner pointed at the LocalSystem profile instead of real user profiles, watchdog
blinding, PDF parser recursion/LZW/decompression bounds, and roughly 90 further
medium/low fixes. Full detail in [`CHANGELOG.md`](../../CHANGELOG.md) and
[`docs/DEEP_AUDIT_2026-07.md`](../DEEP_AUDIT_2026-07.md).

## Behaviour change — read this one

**The GUI memory scan now requires an elevated GUI.** `memory.scan_process` is
elevation-gated because reading another process's memory layout across a privilege
boundary is an ASLR-layout disclosure. If you run the GUI unelevated, that feature will
refuse rather than silently return nothing. This is intentional, not a regression.

## Known costs and limitations

We would rather state these than have you discover them.

- **Rescans are I/O-heavy.** Closing the scan-cache poisoning hole means the cache now
  hashes a file's full contents to confirm it is unchanged — and that check runs on
  cache *hits*, precisely when no scan follows. Re-scanning an already-cached large
  corpus therefore re-reads it end to end. This is retained deliberately: every cheaper
  scheme (a prefix, or sparse sampling) leaves byte ranges unread, and those ranges are
  exactly where an attacker hides the payload with size and mtime pinned. The cost is
  the price of the fix, not an oversight.
- **The kernel ETW runtime layer is still not confirmed working on a live machine.**
  The process-lineage monitor and the WeedHack behavioural campaign tracker are wired
  and unit-tested, but no run has yet verified that the kernel session actually
  delivers events. If you run elevated and
  `runtime.status → weedhack_campaigns.image_load_etw.events_seen` stays at 0, that is
  why. Signature scanning, ARGUS static analysis (including the JAR and PDF layers),
  the IOC list, and the snapshot-based process lineage are all unaffected.
- **EtherHiding HTTP detection remains dormant** — the Windows WinHTTP/WinINet ETW
  providers do not expose HTTPS request bodies, so the selector it looks for is not
  observable. The pipeline is in place for a future body source.
- **Detection efficacy is unmeasured.** There is no published true-positive or
  false-positive rate for the ARGUS heuristic scoring yet. That measurement is the next
  piece of work.

## Verification

- `cargo check --workspace` — clean, zero warnings.
- `cargo test --workspace` — **743 tests, all green.**
- `tsc --noEmit` and the GUI production build — clean.
- The audit diff was re-reviewed across five dimensions with adversarial verification:
  6 findings confirmed, 19 refuted.
- Release artifacts were version-verified end to end: the bundled `sentinelld.exe` and
  `argusd.exe`, the GUI executable's version resource, and the filename inside the
  update signature all read `0.1.12`, and the shipped daemon binary was checked to
  actually contain the new fixes.
