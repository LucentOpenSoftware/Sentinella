# Sentinella v0.1.10 — WeedHack runtime detection stack

End-to-end detection for the **WeedHack** Minecraft-themed Malware-as-a-Service campaign — static attribution on disk, behavioural correlation at runtime, privacy-safe diagnostics. Eight waves of work consolidated into one release. 870 tests workspace-wide (up from 312 at v0.1.9 entry).

## Install / Upgrade

**Existing v0.1.9 installs** auto-update from the GUI on next launch (signature pinned in `tauri.conf.json` validates — no fresh install needed).

**Fresh install / manual upgrade**: download `Sentinella_0.1.10_x64-setup.exe` below and run it elevated.

After install, verify the new runtime layer is live:

```powershell
.\scripts\collect-weedhack-runtime-diagnostics.ps1
```

You should see a `weedhack_campaigns` block in the JSON. If the daemon is running elevated, `image_load_etw.running: true`.

## Highlights

### WeedHack family detection — disk + runtime

- **JAR layer** (`argus`). Detects WeedHack Stage 1/2/3 strings, the JNIC-obfuscated namespaces (`dev/jnic/{lXpXvp,BSOMwJ,fwcMeR}`), the EtherHiding function selector `0xce6d41de`, persistence path family (`Microsoft\SecurityUpdates`, `Updater.vbs`, `Pjibf.exe`), and the v0.2 fallback IP `45.141.119.34`. Synthetic test corpus scores Stage 1 / 2 / 3 / obfuscated builds all Malicious.
- **PDF layer** (`argus`). Covers the `jonaslejon/malicious-pdf` generator family — `/Launch`, `/GoToE+UNC`, `/URI`, JavaScript triggers, embedded executables, XFA submission, obfuscation-level-4 `eval(atob(...))` wrappers via `lopdf 0.34`.
- **IOC list expansion**. Four confirmed WeedHack SHA-256 samples (MalwareBazaar + Triage) documented from McAfee Labs research and 0xresetti's technical writeup.

### Runtime correlator with three-tier campaign model

- **`WeedHackCampaignTracker`** consolidates signals across PID lineage and 20-minute windows into one of three confidence tiers — **Suspicious** (observe-only), **HighConfidence** (alert), **Confirmed** (eligible for quarantine through existing `ConvergenceLedger`).
- Pathognomonic signals (Pjibf binary, JavaSecurityUpdater scheduled task, EtherHiding selector) escalate faster than corroborators.
- Bounded at 64 concurrent campaigns (~16 KiB worst case). PID-reuse safe.
- Three existing PLM scan sites (watcher, IPC scan, idle scanner) now feed the tracker — **no bypass, no second verdict path**.

### Real Windows ETW pumps, two sources

- **ImageLoad ETW pump**. Detects unsigned DLLs loaded into Chrome/Edge/Brave/Firefox from `%TEMP%` or `%APPDATA%` under a `javaw.exe` ancestor. Shares the existing `SentinellaPLM` kernel session via `EVENT_TRACE_FLAG_IMAGE_LOAD`. Rate-limited, dedup-guarded, signer-gated.
- **FileIO wallet-harvest pump**. Detects ≥3 distinct wallet/credential stores read by the same `javaw.exe` PID within 10 seconds. Shares the same session via `EVENT_TRACE_FLAG_FILE_IO_INIT`. Aggressive callback-side filter (~99% of file opens drop before any expensive work). Canonical store keys collapse Chrome/Edge/Brave Login Data into one slot so the stealer can't game the threshold by reading every browser fork.

### WinTrust-backed signer verification

- New `argus::layers::authenticode::verify_for_signer_verdict` public API. Trusted modules drop pre-lineage; Unknown signers still go through the path+lineage gate.
- Bounded LRU cache by `(path, size, mtime)` — cap 4096, TTL 1 hour. Steady-state cost trends to "0 verifier calls" on a healthy box as the cache warms.

### EtherHiding HTTP pipeline (honest dormancy)

- Full pipeline for detecting Java-originated Ethereum RPC POSTs carrying the WeedHack selector. Public ingestion API `PlmMonitor::ingest_http_post()`.
- **Dormant in production** because `Microsoft-Windows-WinHTTP` and `WinINet` ETW providers do not expose HTTPS request bodies — by design. The `body_unavailable` counter surfaces the coverage gap honestly rather than faking detection. Pipeline is ready to consume events from any future source that can supply bodies (Java JNI agent, user-mode hook).

### Privacy guarantees (test-enforced)

- No full file path appears in any diagnostics surface.
- No full URL appears in any diagnostics surface.
- No HTTP body, wallet address, or token appears in any diagnostics or finding narrative.
- Defense-in-depth scrubber in `scripts/collect-weedhack-runtime-diagnostics.ps1` re-scrubs by field name and content shape.

### UI + diagnostics

- New **WeedHack Campaigns** panel on the Intelligence page. Hidden when no data; red badge only on Confirmed. i18n in en / es / fr / de.
- `runtime.status.weedhack_campaigns` IPC block with per-pump sub-blocks (`image_load_etw` with `signer` sub-block, `fileio_etw`, `http_intake`).
- `diagnostics.export` mirrors the same block for offline analysis.
- `health` endpoint (public, no auth) gains two lightweight integers: `weedhack_active` and `weedhack_last_confirmed_unix`.
- `docs/WEEDHACK_LIVE_VALIDATION.md` — operator runbook for admin/non-admin baseline runs, synthetic-positive injection, FP tuning workflow with one-PR-per-FP discipline.

## Constraints honored

- **No bypass of `ConvergenceLedger`** — every signal flows through the existing verdict pipeline.
- **No auto-quarantine on ETW-only signals** — Suspicious tier is observe-only (Medium / weight 10 → LowSuspicion floor). Confirmed requires either three distinct signals OR a pathognomonic signal plus a corroborator.
- **Detector behaviour unchanged** across all 8 waves of work — verified by a regression test that asserts `evaluate_chain` output is identical before and after the campaign tracker drives.

## Limitations (read before reporting bugs)

- **WinHTTP/WinINet body capture is dormant**. The providers exist but do not surface HTTPS request bodies. EtherHiding signals only fire when an upstream source is wired — none ship in v0.1.10.
- **Live 30–60 minute baseline numbers** must be captured by the operator following the runbook. `cargo test` exercises every code path but cannot measure real-world CPU/memory/event-volume.
- **No Java JNI agent and no Detours hook in this release**. Architectural decision was to lock down the defensive surface (detectors, tracker, diagnostics, privacy) and ship — instrumentation surfaces are a future release.
