# Sentinella v0.1.11 — Final release (bug-fix & hardening pass)

The last planned Sentinella release. A focused remediation pass over the
v0.1.10 WeedHack stack, driven by a four-front internal audit: memory
safety, concurrency, IPC/privacy, and parser robustness. No new features —
just fixing what the audit found and being honest about what couldn't be
verified.

## Install / Upgrade

**Existing v0.1.10 installs** auto-update from the GUI on next launch
(signature pinned in `tauri.conf.json` validates).

**Fresh install / manual upgrade**: download `Sentinella_0.1.11_x64-setup.exe`
and run it elevated.

## What changed

### Security / DoS

- **PDF decompression-bomb DoS (HIGH)** — a few-KB crafted FlateDecode
  stream could inflate to multiple GB and OOM the scan engine. Decompression
  is now hard-bounded; a bomb truncates at the cap instead of exhausting
  memory. Regression-tested with a 64 MiB→few-KB bomb.
- **Unauthenticated detection-status leak (MEDIUM)** — the public `health`
  endpoint exposed whether/when a WeedHack campaign was confirmed, a useful
  oracle for an attacker timing cleanup. Removed; that data now lives only
  on the authenticated `runtime.status` / `diagnostics.export` endpoints.
- **ETW callback UB guards (LOW)** — null/zero-length event data is rejected
  before the unsafe slice construction in all three kernel callbacks.

### Detection correctness

- **ImageLoad / FileIO ETW detectors were silently dead on real systems
  (HIGH)** — the path extractor only recognised DOS `C:\…` paths, but the
  Windows kernel delivers NT device paths (`\Device\HarddiskVolumeN\…`).
  The detectors now extract both. (Unit tests had passed only because they
  synthesised `C:\` paths — a reminder that green tests aren't field
  validation.)
- **Wallet-harvest pacing evasion (MEDIUM)** — the burst window was
  tumbling, not sliding, letting a throttled stealer pace its reads to
  never trip the threshold. Now a true sliding window.
- **Campaign flush-by-flood (MEDIUM)** — an attacker spawning many
  short-lived process trees could flush an in-progress Confirmed campaign.
  Eviction now protects high-confidence campaigns.
- **Authenticode catalog carve-out (LOW)** — catalog-signed Windows system
  DLLs are no longer mis-classified as untrusted.

### Robustness

- ETW session no longer leaks on `OpenTraceW` failure.
- Access-denied detection no longer over-matches error codes 50-59/500-599.
- A double-counted FileIO diagnostic counter was fixed.

### GUI

- The WeedHack Intelligence panel no longer crashes the page on an
  unexpected/partial daemon payload (defensive tier-badge + signals guards).

## Honest limitations (please read)

- **The kernel ETW session is not verified to deliver events on a live
  box.** The shared session is created as a real-time logger but does not
  set the Win8+ system-logger mode that the documented ETW contract
  requires for kernel `EnableFlags` to take effect. This was *not* changed
  blindly in an unvalidatable final release — a wrong change risked
  destabilising the shipped process-lineage monitor. **If you run elevated
  and `runtime.status → weedhack_campaigns.image_load_etw.events_seen`
  stays 0, that's the cause**, and the documented next step is to add
  `EVENT_TRACE_SYSTEM_LOGGER_MODE` to the session's `LogFileMode` and
  re-test. The chain-based WeedHack signals still work via the snapshot
  lineage graph regardless, and all static detection (JAR, PDF, IOC) is
  unaffected.
- **EtherHiding HTTP capture remains dormant** (no HTTPS body source), as
  in v0.1.10.
